# HM3D-M³ 官方 baseline 与本地 runs 指标对齐

> 生成日期：2026-10-30。官方数字取自 arXiv 2610.20121v1（Table II / Table III，val 1000 episodes）；
> 本地数字取自 `cache/sim_eval*.json`（400 episodes，shards 94–97，起点帧，navmesh 测地路线）。

## 0. 先看结论

1. **官方最好的端到端结果是 LaViRA-M³ 的 SR 41.0 / SPL 20.3**（Table II）；纯分配策略（导航策略固定）从 random 的 16.8 SR 提到 HiGA-DAgger 的 37.9 SR，**分配一项值 +21.1 SR**。
2. **本地最好的可部署分配模型是 `df-mgeo-full94`，MSPL 0.8388 / regret 1.110**，与 oracle 测地 Hungarian 的 0.8417 / 1.116 只差 **0.003**——在“感知与执行都完美”的假设下，分配层已经接近饱和。
3. **两套数字不能直接比**。本地 SR 构造上恒为 1（路线到达即算找到），官方 SR 由“1 m 内声明 + 检测/匹配”决定；本地 0.84 的 MSPL 不等于官方 41% 的 SR。真正可对齐的是官方 **Table III**（只换分配策略），不是 Table II。
4. 结论指向同一处：**分配不是当前端到端的瓶颈，感知、停靠判定与实例验证才是**；但把分配做差（random）会直接损失 21 个 SR 点，所以它是必要不充分条件。

## 1. 三层评测口径

| 层级 | 输入 | 成功判定 | 官方对应 | 本地对应 |
|---|---|---|---|---|
| 端到端 | RGB-D + 导航策略 + 感知 | 站在目标 1 m 内声明，检测/匹配确认 | Table II（VLFM / EGO-Swarm / Co-NavGPT2 / DM3-Nav / HiGA / LaViRA-M³） | 无 |
| 分配层（固定策略） | 分配结果 + 真实导航执行 | 同上 | Table III（random / rule-based / HiGA-BC / HiGA-DAgger） | 无（需跑 habitat） |
| 分配层 oracle 路线 | 分配结果 + navmesh 测地 + 完美感知 | 路线经过目标即算找到 | 无 | `m3assign/sim_eval.py` |

本地 `sim_eval.py` 用的是官方 `benchmark.metrics.team_metrics`，**MSPL 公式与论文相同**：`SR · d* / max(d*, T)`，`d*` 为 oracle team makespan，`T` 为团队 makespan（最慢 agent）。差别只在 `T` 的来源：本地是用分配顺序累加的 NN-TSP 测地长度，官方是策略真实走过的路径。

## 2. 官方 Table II：端到端（val 1000 episodes）

| 方法 | 协调方式 | SR↑ | SPL↑ | ON↑ | TN↑ | IIN↑ |
|---|---|---:|---:|---:|---:|---:|
| VLFM | 共享地图上各自独立 | 16.1 | 11.8 | 24.5 | 17.7 | 5.9 |
| EGO-Swarm | 几何分散 | 23.7 | 10.7 | 35.5 | 28.0 | 7.5 |
| Co-NavGPT2 | 中心化 VLM 前沿分配 | 24.5 | 9.4 | 37.3 | 28.8 | 7.6 |
| DM3-Nav | 去中心化意图广播 | 26.6 | 9.9 | 35.9 | 30.4 | 14.2 |
| **HiGA**（训练式分配） | 学习式目标分配 | **37.9** | 7.1 | **53.0** | 40.2 | 18.8 |
| **LaViRA-M³**（训练-free） | 共享目标板 + 进度分析 | **41.0** | **20.3** | 38.6 | **40.9** | **41.4** |

两套 baseline 的强弱互补：HiGA 强在类别目标（ON 53.0）但图像目标弱（IIN 18.8）、效率最差（SPL 7.1）；LaViRA-M³ 强在实例目标（IIN 41.4 / TN 40.9）且最省路（SPL 20.3），但类别搜索落后 HiGA 14.4 点。

## 3. 官方 Table III：固定导航策略、只换分配

| 分配策略 | SR↑ | SPL↑ | ON↑ | TN↑ | IIN↑ |
|---|---:|---:|---:|---:|---:|
| random | 16.8 | 2.7 | 22.7 | 17.3 | 8.3 |
| rule-based（按代价匹配检测候选） | 21.6 | 4.3 | 29.5 | 19.7 | 11.3 |
| HiGA-BC（行为克隆 oracle 分配） | 34.1 | 6.0 | 44.7 | 41.7 | 14.3 |
| HiGA-DAgger（+ 3 轮 DAgger） | 37.9 | 7.1 | 53.0 | 40.2 | 18.8 |

**这张表才是本地分配评测的对照物。** 可读出的量级：
- random → rule-based：+4.8 SR（便宜的先验就有用）；
- rule-based → BC：+12.5 SR（学出来的分配显著优于规则）；
- BC → DAgger：+3.8 SR（在线纠错还能再挖一点）；
- 合计 random → DAgger：**+21.1 SR / +4.4 SPL**。

LaViRA-M³ 的协调通道消融（同一张表下半部分）：去掉 shared goal board 掉 7.8 SR（41.0→33.2），去掉 shared progress 掉 3.7 SR（41.0→37.3），两者都去掉掉 11.7 SR（→29.3）。换成 HiGA 的窄视场相机掉 11.4 SR（→29.6，但 SPL 升到 23.0）——**视场是它 SR 优势的一大来源**。

## 4. 本地分配层评测：经典策略（couple3r ckpt，400 eps）

| 策略 | 信息 | MSPL↑ | SPL_sum↑ | makespan↓ | regret↓ | Gini↓ | 与 oracle 一致↑ |
|---|---|---:|---:|---:|---:|---:|---:|
| oracle | 真值分配 | 1.0000 | 1.0000 | 10.13 | 1.000 | 0.217 | 1.000 |
| hungarian | 真测地代价（oracle 信息） | **0.8417** | 0.9241 | 12.57 | 1.116 | 0.155 | 0.564 |
| balanced | 测地 + 负载均衡 | 0.8158 | 0.8494 | 13.38 | 1.171 | **0.117** | 0.490 |
| nearest | 最近目标贪心 | 0.7941 | 0.8858 | 14.13 | 1.197 | 0.156 | 0.469 |
| teacher | 官方数据里的教师分配 | 0.7807 | 0.8312 | 13.88 | 1.191 | 0.223 | 0.676 |
| hungarian_eucl | 平面欧氏代价 | 0.7823 | 0.8309 | 13.51 | 1.208 | 0.164 | 0.422 |
| hungarian_bfs | 数据内 `travel` 代价 | 0.7727 | 0.8267 | 13.97 | 1.247 | 0.170 | 0.446 |
| geometric | 几何分散 | 0.7328 | **0.9868** | 15.15 | 1.415 | 0.471 | 0.575 |
| random | 无信息 | 0.6649 | 0.8062 | 16.82 | 1.502 | 0.326 | 0.350 |

三个必须注意的点：

1. **`teacher` 不是 oracle**。教师分配 MSPL 0.7807，比 oracle 测地 Hungarian 低 0.061；这与 [teacher_100k_audit.md](teacher_100k_audit.md) §7 的结论一致——教师是“默认保留承诺、只在 found 事件上重决策”的在线策略，不是 makespan 最优解。所以“复现教师”和“做好分配”是两个目标，别混。
2. **指标选择会换冠军**。按 MSPL（makespan 归一化，官方主指标）排序 Hungarian 第一；按 SPL_sum（总路程）排序则是 geometric 第一（0.9868）但它的 MSPL 只有 0.7328。团队目标写“最慢的 agent 多快完成”还是“总路程多短”，结论不同。
3. **数据里的 `travel` 基本无信息**：hungarian_bfs（0.7727）甚至低于平面欧氏（0.7823），远低于真测地（0.8417）。与审计报告 §3 的 ρ=0.05 相互印证。

## 5. 本地模型 runs（可部署分配，`assignnet_hung` = 模型打分 → 一对一 Hungarian）

| run | 关键配置 | best step | val teacher_acc | test-time 输入 | MSPL↑ | SPL_sum↑ | makespan↓ | regret↓ |
|---|---|---:|---:|---|---:|---:|---:|---:|
| couple3r（定版） | couple3 | 600 | 0.332 | map+heat+travel | 0.7765 | 0.8287 | 13.64 | 1.218 |
| contract3 | +contract | 1600 | 0.751 | +承诺 | 0.7894 | 0.8382 | 13.31 | 1.201 |
| contract3-seed1 | +contract, seed1 | 2000 | 0.754 | +承诺 | 0.7966 | 0.8468 | 13.29 | 1.180 |
| contract3-full94 | 94 训练 shard | 5000 | 0.752 | +承诺 | 0.7943 | 0.8459 | 13.33 | 1.168 |

| df-full94-a2 | DF 2.0 + CE 1.0 | 5000 | 0.757 | +承诺 | 0.7943 | 0.8438 | 13.55 | 1.179 |
| startbc94 | 只训起点帧，BC | 400 | 0.264 | 起点帧专用 | 0.7841 | 0.8343 | 13.38 | 1.205 |
| startdf94 | 只训起点帧，纯 DF | 800 | 0.258 | 起点帧专用 | 0.7924 | 0.8340 | 12.62 | 1.201 |
| **df-mgeo-full94** | +mapgeo 真平面距离 | 1000 | **0.780** | +目标地图坐标 | **0.8388** | 0.8956 | **12.35** | **1.110** |
| df-mgeo-full94-s2 | 同上，第二 seed | 5400 | 0.778 | 同上 | 0.8323 | 0.8939 | 12.59 | 1.107 |
| **bc-mgeo-full94** | 同上，纯 BC | 600 | 0.779 | 同上 | 0.8361 | **0.8969** | 12.42 | 1.113 |

怎么读这张表：

- **mapgeo 是唯一一个把 MSPL 从 0.79 拉到 0.84 的改动**（+0.045），其余改动都在 ±0.01 噪声里。原因是审计 §3：`travel` 缺测严重、与真测地几乎无关，补上真实目标坐标才把拓扑信息给到模型。
- **contract 的收益在训练指标上巨大（teacher_acc 0.33→0.75），在起点帧路线指标上不显著**（0.7765→0.7894，p=0.14，见审计 §8）。这是因为起点帧 `contract ≡ −1`，只有 periodic/found 帧有信息，而 sim_eval 只评起点帧。
- **决策聚焦（df）单独用没有收益**（0.7957 vs 0.7943，同量级），和 mapgeo 叠加时也没有超过纯 BC 的 mgeo 版本（0.8388 vs 0.8361，差 0.0027）。目前证据不支持“DF 比 BC 更好”。
- **可部署 vs oracle 的差距只剩 0.003**：0.8388（模型打分 + 测地 Hungarian 解码）vs 0.8417（真测地代价 Hungarian）。也就是说，在起点帧这个评测里，模型已经把“该看的信息”压缩得足够好，继续调分配层收益极小。

## 6. 两套数字怎么对齐

| 可比量 | 官方 | 本地 | 说明 |
|---|---|---|---|
| random → 学习式分配 | +21.1 SR（16.8→37.9） | +0.174 MSPL（0.665→0.839） | 方向一致，说明分配确实重要；绝对值不可比 |
| 学习式 vs 规则 | +16.3 SR（21.6→37.9） | +0.044 MSPL（0.794→0.839，对 nearest） | 本地差距更小，因为本地没有感知噪声放大分配错误 |
| 相对 oracle 的效率 | 无（论文不报 oracle 分配上界） | 0.998（0.839/0.842） | 本地独有的诊断量 |
| 协调通道消融 | shared board +7.8 SR、shared progress +3.7 SR | 无对应 | 本地没有跨 agent 通信建模 |
| 相机/视场 | 窄视场 −11.4 SR | 无对应 | 本地假设完美感知 |

**一句话**：官方数字回答“端到端能做到多少”，本地数字回答“分配这一层还能挖多少”。目前后者只剩 0.3%，前者还有 20+ 个点——瓶颈明确在感知与验证。

## 7. 不可比项清单（写论文/汇报时必须声明）

| 项 | 官方 | 本地 |
|---|---|---|
| 感知 | 检测器 + CLIP/keypoint 匹配，1 m 内声明 | 路线经过即算找到（完美感知） |
| 执行 | habitat 连续动作 + 预算，真实路径长度 | 分配顺序累加的 NN-TSP 测地长度 |
| 评测帧 | episode 全程 | 只取起点帧（`event_id` 最小） |
| 规模 | 1000 val episodes | 400 episodes（shards 94–97） |
| 模态 | ON / TN / IIN 分列 | 合并，不分模态 |
| 团队 | K∈{2,3,4}，M∈{3,4,5} | 同（K_MAX=4，M_MAX=5） |
| 指标 | goal-level SR + makespan-normalized SPL | 同公式，但 SR 恒 1，只有 MSPL/regret 有区分度 |

## 8. 复现命令

```bash
cd m3-assign   # 仓库根目录
# 训练（示例：当前最好配置）
python -m m3assign.train --train-shards 94 --val-shards 4 --epochs 40 --batch 512 \
    --lr 6e-4 --couple-iters 3 --contract 1 --mgeo 1 --df-weight 2.0 --name df-mgeo-full94
# 分配层评测
python -m m3assign.sim_eval --episodes 400 --detail 400 \
    --ckpt runs/20261028-225833-df-mgeo-full94/best.pt --out cache/sim_eval_pair_mgeo.json
```

官方 baseline 复现见 `hm3d-m3-code/sim-code/AGENT_SETUP.md`（需要 HM3D 场景 + GroundingDINO + Qwen3.5-27B 端点）。

## 9. 下一步（按性价比排序）

1. **补 ON/TN/IIN 分模态指标**。本地现在只有合并口径，而官方的核心区分就在模态上；没有这一列，任何“超过 HiGA”的说法都不成立。
2. **接一层固定导航策略做真实执行**（哪怕用现成的 OVON 策略 + 简化停靠），把本地从“分配上界”变成“分配层消融”，才能直接对 Table III。
3. **把 random / rule-based / nearest / Hungarian 四条基线固定进评测脚本输出**，论文里不要只报 oracle 匈牙利；同时报 MSPL 与 SPL_sum，避免“选指标换冠军”。
4. 分配层已接近 oracle，**不建议继续投入调分配**；剩余收益在“目标确认/停靠判定”和“跨 agent 共享进度”，对应 LaViRA-M³ 的 +7.8 / +3.7 SR。
